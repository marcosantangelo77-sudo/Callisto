## CONFIRMED DEFECTS — ranked

### A · CRITICAL · families 1+3+seam — gate rejection does not survive resume
`tools/pipeline/engine.py:808-816` replays checkpoint payload fetches into
the ledger via `ckpt.replay_ledger` BEFORE any gate runs; the payload's
`rejections` list is restored onto the trace (`engine.py:1081`) but never
handed to `ledger.record_gate_rejection()` on the resumed process. Bytes the
live run's relevance gate REJECTED re-mint as PRIMARY, and `seal_guard`
returns SEAL over them. Differential control: the live path supersedes
correctly, proving the divergence is the resume seam. This reopens exactly
what R4/R4b closed, through the boundary those fixes didn't cover.
Repro: `test_a_gate_rejection_lost_across_resume_lauanders_bytes`.

### B · HIGH · family 1 — unkeyed regime makes integrity self-verifying
The documented default deployment sets no key (`harness_key() -> None`,
verified live). Then `partition_admissibility`'s authentication is a no-op
and integrity rests solely on `content_sha256` — which travels INSIDE the
same editable JSON file as the bytes it hashes. Tamper body + digest →
replayed as PRIMARY, seal_guard SEALs. The keyed path exists but nothing in
production sets the key: a verification layer whose input is missing.
Repro: `test_b_unkeyed_tamper_self_verifies_and_seals`.

### C · HIGH · families 2+6 — round() still quantises confidence UP in two places
`floor_conf` exists in `agp/thresholds` precisely to kill upward rounding,
but:
- `agp/claims.py:141,149 recompute_confidence` uses `round(...)` — sweep:
  ~12.6% of random claims GAIN confidence by quantisation alone (long-lived
  belief journal inflating its own history);
- `tools/pipeline/engine.py:580` sealed confidence uses `round(max(0,min(est,
  ceil)),2)` — ~50% of draws round up. The comment pins "historical rounding
  preserved verbatim", which preserves the defect the architecture forbids.
Repros: `test_c_*`.
