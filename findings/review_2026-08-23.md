## DEFECT R1 — CRITICAL: preregistration seals are still never verified
(family #1, fifth/sixth instance; flagged by fix_a6's own sweep, unfixed)

- `Preregistration.verify_seal()` (agp/preregistration.py:181) has ZERO
  production callers. `from_dict()` line 399 sets `_sealed = bool(seal_hash)`
  — presence of ANY hex string counts as sealed.
- `ClaimStore.load()` (agp/claims.py:402) verifies only the journal prev-hash
  chain, which is unkeyed SHA-256 an attacker recomputes for free (also
  flagged in fix_a6's sweep, item 4).
- Consequence, demonstrated end-to-end: rewrite `confirm_markers` in a saved
  claim's journal, recompute two hashes, reload — `verify_seal()` returns
  False on the loaded claim, yet `resolve()` scores against the forged
  criteria anyway and mints **CONFIRMED at confidence 0.75 with zero
  divergences**. The "commit before evidence" property, the thing MORNING_REPORT
  lists as verified working, does not survive a round-trip through storage.

Repro: tests/test_review_prereg_seal_unverified.py (3 failing tests, including
the end-to-end journal tamper). Fix is small: `score()` should raise when
`not self.verify_seal()`, and/or ClaimStore.load() should check the embedded
seal. Note the irony that fix_a6 fixed A6 by *wiring* verify_artifacts — and
left its own swept sibling unwired.

## DEFECT R2 — HIGH: B1 fix half-landed — the trusted-formula path takes
untrusted bytes (family #2; fix lands in one copy, the trust boundary in
another stays open)

fix_b1.md guards every fetched-bytes cell and states the ONLY unguarded
writes are `spec["model"][*]["formula"]`, "produced by OUR code paths … never
from fetched bytes." I checked who enforces that provenance: nothing. It is a
comment. `build_workbook(spec)` accepts an arbitrary dict, and today only

property held by convention is violated by any new caller (the exact wording

`formula='HYPERLINK("http://evil","click")'` produces a cell with
data_type 'f'. Any future plugin, restored artifact spec, or model-supplied
tool argument reopens the injection. Blast radius today is limited (both
current producers are code-generated); the defect is the unenforced boundary.

Repro: tests/test_review_b1_formula_trust_boundary.py (fails). Reasonable
fixes: validate formula shape (cell-refs/operators only), or require formulas
to carry a signature from the producing module, or hash-pin allowed formulas.

## SHAPE WORTH NAMING (candidate addition to PATTERNS.md)

Not a new family so much as family #1's second-order form: **a verification
function whose result is computed correctly and then thrown away** —
verify_seal() works (returns False on tampered input, I tested it) but no
caller consumes the answer; likewise the `expected` digest in claims.load().
The audit question "what calls this?" catches it, but a sharper version:
*after every verify_* call, follow the boolean. If neither branch acts on it,
the check is decoration.* Three instances in one file pair here.
