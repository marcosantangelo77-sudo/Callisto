## THE FIX (this run)

Parallelize the per-round source fan-out inside one leaf:
each spec's fetch+gate runs in its own thread via `asyncio.to_thread` /
executor, results are merged back in SPEC ORDER so:

- trace.admitted / rejected / queries / rounds keep exact serial order;
- scratch-ledger record order (replayed by the engine in leaf order) stays
  byte-identical to the serial run;
- `relevant_titles`, refinement, terminator decisions unchanged (they are
  computed AFTER the round completes, from round-ordered results);
- errors: a failed source still just excludes itself and continues —
  exception selection per source is local to that source, no cross-source
  ordering hazard exists;
- `_RateLimiter` is already thread-safe per source spec, so politeness
  intervals are preserved exactly (per-source spacing unchanged; sources
  already fetched concurrently ACROSS leaves, so per-host concurrency does
  not increase beyond what parallel leaves already produce).

Predicted post-fix retrieval: max-over-sources ≈ F + rate-limit spacing ≈
~1s instead of Σ ≈ 4.06s → end-to-end wall ≈ 7s vs 10.16s (~1.45×) at
M=3s/F=0.8s; grows with source count and F (live HTTP F≫fixture F).
