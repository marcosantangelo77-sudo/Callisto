## THE PRICED TABLE (structure × per-unit latency)

Two transport assumptions. M = per-model-call latency, F = per-fetch latency.

Pre-fix CLI (measured on this branch today: 7.6s for a trivial `hermes -z`;
brief baseline 11.3s/call round trip):

| section            | formula            | M=11.3s F=1.0s |
|--------------------|--------------------|---------------:|
| decompose          | 1×M                |         11.3s  |
| leaf section       | 5×(4×F + 2×M)      |        124.3s  |
| adversary          | 1×M                |         11.3s  |
| **wall**           |                    |       ~147s    |

(The historical 2,625s run had more rounds/retries per leaf; same shape.)

Post-fix persistent transport (assume M=3s inference-only, F=0.8s):

| section            | formula            | seconds |
|--------------------|--------------------|--------:|
| decompose          | 1×M                |    3.0  |
| leaf section       | 5×(4F + M)         |   31.0  |
| adversary          | 1×M                |    3.0  |
| **wall**           |                    |  **37s**|

**84% of post-fix wall time is the leaf section, and it is strictly serial:**
`engine.run()` processes leaves one at a time — sync urllib fetches that block
the event loop, then an awaited model call, then the next leaf. Leaves are
independent: leaf k's retrieval and answer depend on leaf k only. This is the
next bottleneck after the transport fix.

## THE FIX (this run)

Overlap the independent leaves while preserving byte-identical outputs:

- **Phase A**: all leaves' retrieval run concurrently off-loop
  (`asyncio.to_thread`), each writing a scratch provenance ledger; merges
  replay into the real ledger in leaf order → identical ledger state, no
  cross-thread mutation, no locks, no `agp/` edits.
- **Phase B**: all leaves' answers run concurrently on the loop; evidence
  items are returned per leaf and appended to `session.evidence` in leaf
  order afterwards → identical evidence order feeding conclusion + adversary
  + checkpoints.
- Errors: `gather(return_exceptions=True)`, then raise the first exception in
  LEAF order — identical error-selection to the serial loop.
- No caching anywhere near a retrodiction cutoff (none added). The adversary
  stays its own model call. Nothing that can lower a gate changed.

Predicted post-fix wall: 3 + max(4F+M) + 3 ≈ **9–10s vs 37s (~3.8×)**; the
win grows with leaf count.
