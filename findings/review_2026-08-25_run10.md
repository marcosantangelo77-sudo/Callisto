### B · HIGH · family 3 — the zero-result echo hole admits EVERY REAL adapter envelope, not just run 9's synthetic one
Run 9 pinned `{"meta": {"query": q}}`. I probed the gate with the actual
zero-result/error shapes the adapters emit. All admit:

| Shape | Admitted |
|---|---|
| OpenAlex-style `{"meta": {"query": q, "count": 0}, "results": []}` | True at **100%** |
| SemanticScholar-style `{"total": 0, "data": [], "query": q}` | True |
| FRED error envelope `{"error_code": 420, ..., "search_text": q, "count": 0}` | True at **100%** |

Root cause unchanged since run 8: `extract_text` judges the whole payload,
including request-echo fields. FRED's case is the worst because its quota
exhaustion error (a known live condition — BLS no-key = 25/day, FRED similar)
echoes the question verbatim and scores perfectly. The empty result set is
not merely admitted; it is admitted with maximum confidence. Structural fix
remains what run 9 proposed: judge only on result content nodes, or refuse
envelopes whose parsed text adds nothing outside the echoed query.
Repros: three `test_zero_result_*` tests in the deliverable.
