## PART 3 — NEW DEFECTS (family-tagged; all repro'd)

### R1+R2 (families 1 & 3): RestSource._record mints PRIMARY before anyone looks at the status code
`_do()` calls `self._record(url, status, body, …)` unconditionally; `_record`
writes `primary=True` into the ledger for ANY status, then `get()` returns.
`get_json` never consults `rec.status`; only retrieval's `_fetch_one` does.
Probes:
- 502 + JSON error body via `get()`: ledger minted `(fake_fetch, True)` BEFORE
  the caller can react.
- `get_json()` on 503: RETURNS the parsed error body as data.
Direct adapter callers (bea/census/cmefedfut methods, anything outside
retrieval's fan-out) get error bodies handed to them as evidence-shaped
dicts whose provenance already says PRIMARY. Same shape as K1/C1/W5: the
check (status handling) exists but not where the trust decision is made.

### R3 (family 1, deeper than SL-2): provenance_is_intact is CIRCULAR on resume
`seal_guard`'s resumed path replays checkpoint fetches into THE REAL LEDGER
first (engine.py resume path / replay_ledger), so by the time
`provenance_is_intact` asks `has_observation(body)`, the answer was made True
by the replay itself. Probe: fabricated body + self-consistent sha256 in a
checkpoint payload → replay mints PRIMARY → intact=True → seal_guard returns
SEAL. Under the documented default (_harness_key() -> None) nothing
authenticates the payload, so anyone who can write the checkpoint file can
mint arbitrary PRIMARY evidence past the seal guard. SL-2 caught the
independence-count lie; this is the byte-level version: the anti-laundering
check verifies bytes against a ledger the same check just filled.

### R4 (family 3): cmefedfut turns a 502 error body into an honest-looking null
`CmeFedFutAdapter.settlements("20250815")` over transport returning
(502, '{"error": "gateway timeout"}') returns
`{"settlements": [], "trade_date": "20250815", "_fetch": {url, sha256-of-error-body, fetched_at}}`.
No status check, no error-body sniffing. Downstream reads zero settlements
as data ("the exchange lists no contracts that day") backed by tier-3
PRIMARY provenance. bea/census have partial shape checks but no status
checks either. Empty-admits-success, again, at a new seam.

### R5 (family 6): engine seam rounds the SEALED number half-UP
engine.py:531: `out.confidence = round(max(0.0, min(ec.estimate, ec.ceiling)), 2)`
while `EstimateCeiling.sealable()` floors — the comment even says the two are
"pinned equivalent", which is true only when proposals are already 2dp.
Sweep: 106,401 / 400,004 cases raise the number (est=0.005, ceil=0.54 → 0.01;
0.5497@0.55 → 0.55 vs floor 0.54). An automated actor raising its own sealed
confidence — the exact thing floor_conf exists to prevent, reintroduced at
the leaf-sealing seam while the parent path uses clamp_parent_confidence
(which floors). Fix landed in one copy; the engine copy kept round().
Family #2 inside family #6.

### R6 (family 6): inherited_ceiling's round(,4) promotes TIERS
run 2 flagged this as "cosmetic-to-minor". It is worse: property sweep
(2,000 random track records) found 144 round-ups, 36 of which CROSS A TIER —
exact 0.89995 → rounded 0.9 flips CORROBORATED → VERIFIED via
tier_ceiling_from_score. The inheritance rule's whole point is that VERIFIED
must be earned by resolved descendants, not granted by rounding.

### R8 (families 4+5): relevance gate admits an EMPTY result set that echoes the question
`RelevanceGate.judge(q, "descriptive", {"query": q, "results": []})` →
admitted=True, coverage 80%. Zero results; admission rests entirely on the
page echoing the query text back. This is the ingestion-side twin of the
original live-run failure ("one irrelevant hit accepted"): token coverage is
a label standing in for content, and volume of overlap stands in for
agreement. Any search API that echoes the query in an empty response sails
through the gate.
