## PART 2 — FAMILY HUNT ON THE NEW LAYERS (where the defects are)

The landing added two brand-new verification layers inside the quant gate.
Fed each an EMPTY/adversarial input, per PATTERNS §3:

### R4-Q1 (family 3): a year followed by a sentence period still satisfies quant_required

`_YEAR_RE = (?:^|[^\w.])(19|20)\d{2}(?:[^\w.]|$)` deliberately excludes `.`
from the after-year class — presumably so "2023.5" isn't split. Consequence:
a year at the END OF A SENTENCE never matches the stripper:

```
_prose_carries_quantity("In 2023 the rate was high")            -> False  (pinned case)
_prose_carries_quantity("The rate was high in 2020.")           -> True
_prose_carries_quantity("Commentators wrote about 2019. ...")   -> True
```

The promoted canary picked the ONE punctuation context where the regex works.
Model answers overwhelmingly end sentences with periods, so the exact input
shape the fix targets ("in 2023 the rate was high"-style date-only prose)
still passes the gate whenever the year lands before a full stop. Same for
glued tokens: `"In FY2020 spending rose."` -> True (the `[^\w.]` before-year
class rejects `Y`). Family #2 shape: the rule exists in the regex and in the
test, but the test's hand-picked input never touches the failing boundary —
PATTERNS §7 verbatim.

Repro: `test_q1_year_before_sentence_period_is_not_quantity`,
`test_q1b_glued_year_token_is_not_quantity`. Fix direction: strip
`\b(?:19|20)\d{2}\b` after removing decimal-attached cases explicitly, i.e.
match year tokens with word boundaries on BOTH sides regardless of adjacent
punctuation, then subtract years from the digit scan.

### R4-Q2 (family 3): sandbox return_value NaN counts as quantitative production

`_produced_quantitative` accepts any `isinstance(rv, (int, float))` that is
not bool. But the child marshaller JSON-round-trips the return value
(tools/sandbox.py epilogue), and Python's json module serialises NaN/Infinity
by default — so `result = float("nan")` reaches the gate as a float:

```
_produced_quantitative("", sbx_with_return_value_nan) -> True
```

A computation that produced NO number (NaN literally means "no value")
satisfies quant_required. Same family as the bare-"ok" defect just fixed:
the gate asks about the TYPE of the return value, not whether a quantity
exists. Repro: `test_q2_nan_sandbox_return_value_is_not_quantitative`.
Fix direction: reject non-finite floats (`math.isfinite`), which also covers
Infinity.
