## THE DEFECT — measured to the second

Single-leaf retrieval of the same question: **91.06s**, 3 rounds, stop reason
"max_iterations". Round breakdown shows `courtlistener` erroring with
`exhausted retries; HTTP 429`. Live reproduction of that exact URL:

```
HTTP 429   Retry-After: 916        # 15 minutes
```

This machine is rate-limited by CourtListener (same environmental class as
the SEC/ClinicalTrials 403s). `RestSource.get()` (tools/sources/base.py:218)
handles it by sleeping `min(max(RA, 2**attempt), MAX_RETRY_AFTER_S=30)` and
retrying — so a source that is cooling down for FIFTEEN MINUTES costs
30+30+30 ≈ **90s of guaranteed-futile blind sleep per fetch attempt**, inside
every retrieval round that selects it. With 4 leaves selected it in parallel,
Phase A's floor is one full 90s ladder regardless of how fast everything else
is. The run-18 e2e wall is ~108s of Phase A for exactly this reason.

The comment above `MAX_RETRY_AFTER_S` already states the principle ("a remote
server must never decide how long we freeze") but the code still burns the
full bounded budget retrying a window it cannot possibly out-wait.

## MODULE CLAIMED THIS RUN: `tools/sources/base.py` — Retry-After decline policy ONLY

(`RestSource.get` 403/429 branch; new pins in tests/test_speed_source_retry_after.py;
one assertion evolved in tests/test_redteam_retry_after_dos.py with justification below.
No other file touched.)

Fix: when a 403/429 carries a `Retry-After` LARGER than `MAX_RETRY_AFTER_S`,
the server has said "come back in a while we cannot serve you now" — sleeping
the cap and re-hitting it cannot succeed. Raise `SourceError` immediately:
the fetch fails this round (exactly as it does today after 90s of sleeping),
the leaf continues without that source, and later rounds' gain-gating can
spend the time on sources that can answer.

- Retry-After ≤ cap: behaviour byte-identical (sleep honoured, retries continue).
- No Retry-After: exponential backoff unchanged.
- 500s/transport errors unchanged.
- Nothing crosses a retrodiction cutoff (no caching); adversary untouched;
  gates untouched. This changes only how soon we ACCEPT a refusal that is
  already certain.

Red-team pin note: `test_redteam_retry_after_dos.py::test_huge_retry_after_
does_not_become_a_huge_sleep` asserts `assert slept` (retry path exercised).
Under the new policy the huge-RA path raises on attempt 1 with ZERO sleeps —
strictly stronger than the bound that test defends (90s → ~0s). The intent
("a remote server must not freeze the pipeline") is preserved; the mechanism
assertion is updated to assert the new, tighter contract.
