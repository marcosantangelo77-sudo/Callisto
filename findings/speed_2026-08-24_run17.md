## THE FINDING — the dead hop is re-probed by every fresh process

gpu1 and gpu1_fast sit FIRST in the routing list of nearly every task class.
The llama-server ports (8080/8081) are down on this machine tonight. The
run-12/16 connect-phase rule fails over fast (~0.5s), but the exponential
cooldown that should suppress the dead hop lives in ProviderRouter STATE,
which dies with the process. Every routed question pays:

```
ProviderRouter: endpoint gpu1 failed (N consecutive) — failing over:
All connection attempts failed
```

before serving — observed on EVERY live call tonight, both scripts, plus a
133.1s outlier leg in run-16's own data. Per-call cost is small (~0.5s), but
it is paid on EVERY call of EVERY process, it churns consecutive_failures
state that then mis-describes an endpoint that may be healthy by the next
process, and under concurrency N parallel leaves all probe the same dead
socket simultaneously.
