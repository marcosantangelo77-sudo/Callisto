## RANKED FINDINGS (each has a failing repro in test_review_2026-08-24.py)

### 1. CRITICAL — ClaimStore "tamper-evident" journal does not detect tampering of the newest entry (F1)
`agp/claims.py::load` verifies only that each line's `prev` matches the
digest of the PREVIOUS line. Nothing verifies a line against its own claimed
state, so editing the LAST journal entry — raising confidence to 0.95,
setting status='confirmed' — replays cleanly. A fresh claim's journal has one
line, i.e. the common case has zero protection. The docstring says a tampered
claim "never silently loads"; MORNING_REPORT.md lists the hash chain as a
headline feature ("rewriting history to flatter yourself breaks the chain").
Repro: r11_01/r11_02 (DID NOT RAISE ClaimError).
Fix shape: store per-entry digest = H(prev_digest ‖ canonical(state)) inside
the entry and verify at load; or keep a separate keyed head-hash.

### 2. HIGH — prereg scoring silently scores against AMENDED criteria by default (F1/F4)
`agp/preregistration.py::score`: `using_amended = criteria is not None or
bool(self.amendments)` and `effective_criteria` returns the latest amendment.
After any amend(), a default score() call uses post-hoc criteria, not the
sealed originals — the opposite of "immutable after seal". The divergence log
names the substitution, but the VERDICT itself comes from the amendment.
Repro: r11_03 (verdict AMBIGUOUS from amended criteria when caller passed
nothing; used_amended=True).
Fix shape: default must be self.criteria (the sealed originals); use the
amendment only when explicitly requested.

### 3. HIGH — cmefedfut W5 date guard bypassed twice, including by its own wrapper (F1/F3)
`attach_market_implied()` — the convenience path documented in its own
findings file as the guard-bearing entry point — wraps bare floats with
`allow_no_provenance=True`, so an unprovenanced probability attaches to any
question regardless of claim_date (r11_04). Separately, a fully-provenanced
benchmark trade-dated AFTER the event attaches whenever the question's
claim_date is None (r11_05): strict_dates fails OPEN on missing input.
The 11 branch tests cover attach_from_derived's refusal paths but never the
wrapper and never the missing-claim_date case.
