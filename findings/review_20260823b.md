## What holds up

- **StasisStop itself is sound.** The rule is genuinely a state-change rule:
  it reads no confidence, fires only after sufficiency is checked, and the
  honest-null classification runs on the stopped trace unchanged. I mutation-
  tested it: a mutant that fires after ANY round still produced an identical
  conclusion state on the null corpus (which is why the golden proof passes)
  — but the engine guard ordering (`not sufficient and not dec.stop`) holds.
- **The stopping-rule study's numbers are real**: measurement script, corpus,
  and JSON artifacts all exist on master and are internally consistent.
- `estimate_gain`'s conservative design is correct where it matters: class
  shortfalls never skip a fetch (a successful fetch could raise the class),
  and duplicate-voice skipping only fires when independence is the ONLY unmet
  requirement.
- The A1/A2/A3 laundering ports (76a3f5c) verified holding in spot checks.

## What does not — ranked

### 1. CRITICAL — refine_query output is dead in planner mode; trace.queries lies about it (family 1)

`IterativeRetriever.retrieve` computes `query = refine_query(query, titles)`
at the end of each round and appends it to `trace.queries`. But every query
is actually authored by `query_builder.build_plan(spec.name, question.text)`
— which reads ONLY `question.text`. Verified live under the socket guard:

    trace.queries = ['apple report quarterly results above consensus',
                     '... consensus earnings wall street expectations',
                     '... expectations next']     <- recorded, NEVER sent
    build_plan('gdelt', q.text).queries[0].kwargs['query']
                 = '"Apple report quarterly results above consensus"'  <- sent, constant

The "iterative" inspect-refine loop's entire refine half never executes in
the default configuration. Consequences:

- Rounds 2..N re-send the round-1 query to already-fetched sources. The only
  reason they ever admit anything new is source rotation/exclusion, not
  refinement.
- **The stasis measurement is partly tautological.** Its stated mechanism for
  pure-cost tails ("refine_query re-queries with overlapping tokens") cannot
  be the cause because refinement is never sent — fixtures return identical
  bytes to an identical query, so state freezing was guaranteed by
  construction. The 26.3%-savings figure survives (the stop rule is still
  sound given frozen state), but "every moving-after-round-1 case moved EVERY
  round" is a property of fixture transport, not of retrieval.
- `trace.queries` is an audit field showing queries that were never issued.

Repro: `test_r1_refined_query_is_actually_sent`.

### 2. HIGH — epsilon-sigma magnitude manufactures "20 robust sigmas" from rounding noise and wins emission ordering (family 6)

Commit 54e9a81 ("anomaly magnitude in robust sigmas") changed `_mad_sigma_range`
to fall back to sigma = max(|med|·1e-6, 1e-9) when history dispersion is zero,
and magnitude to |observed − center|/sigma. Reproduced:

    zero-dispersion history {1,1,1}, FY4=1.00002  -> magnitude 20.0
    genuine history {1.0,1.05,0.98}, FY4=1.45     -> magnitude 15.2
    select_for_emission(limit=1) -> emits 'epsilon_artifact'

A 2-part-per-100,000 wobble outranks a real multi-sigma business break for
the bounded question slots — the exact opposite of MAX_QUESTIONS_PER_EXTRACTION's
stated purpose, and it flows into question text ("Deviation ~20.0 robust
sigmas") that seeds the research pipeline. The commit message claims the new
magnitude is "always interpretable"; for zero-dispersion histories it is
maximally uninterpretable. Fix direction: cap or floor the epsilon-sigma
magnitude (or exclude zero-MAD baselines from magnitude ranking).

Repro: `test_r2_epsilon_sigma_must_not_outrank_genuine_anomaly`.

### 3. HIGH — three registered sources invisible to the health layer, keyed probes can only report BROKEN (families 1+3) — FIXED on unmerged branch

On master, `tools/sources/health.py` probes `cftc`, `sec_fts`,
`semantic_scholar`; the registry registers `cftc_cot`, `sec_fulltext`,
`semanticscholar` (the exact name-mismatch trap PATTERNS.md §2 warns about).
`_build(name)` returns None → probe raises on None-unpack → BROKEN regardless
of live health, while the true names have NO probe. `run_all()` iterates
PROBES keys only; nothing cross-checks PROBES against the registry, so the
blind spot is structurally undetectable by the tool itself. This is precisely
family 1's shape: a verification layer whose input is missing and which fails
in the wrong direction.

`origin/build/source-health` fixes this correctly (_build fallback scan +
probe renames + a coverage test `test_every_registered_source_has_a_probe`)
— but **the branch is NOT merged**. Until it merges, the health layer's
verdict table misreports three sources.

Repro: `test_r3_every_registered_source_has_matching_probe` (pins master;
will pass once source-health merges — flip it then).
