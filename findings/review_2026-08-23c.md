## What does not — ranked

### RV4 (HIGH) — gc() destroys ALL evidence when index.json is MISSING or `{}` (family 3, alive inside the A2 fix itself)

`fix_a14_a2.md` says "an empty dict proves nothing about which objects are
orphans, so deleting on its authority was never sound." True for corrupt
bytes — but `_load_index(strict=True)` returns None only for UNPARSEABLE
json. A missing file returns `{}` (the pre-existing early-return), and `{}`
is also perfectly valid JSON, so the corrupt path never fires for it either.
gc() reads either as "everything is an orphan" and unlinks every object.
Reproduced twice on d8f0b17:

```
test_gc_with_missing_index_file_refuses_to_delete  -> gc removed [ec2f14...]
test_gc_with_empty_index_object_deletes_evidence   -> gc removed [ec2f14...]
```

An absent index proves even LESS than a corrupt one. Fix direction: gc must
refuse unless the index EXISTS and parses to a non-empty dict (or
allow_rebuild regenerates from objects). One-line shape change in gc();
both repros then pass. Note the red-team suite (test_gc_after_corrupt_index…)
only ever exercises corrupt bytes — family 7: the test inputs never touch the
absent-input boundary.

### RV5 (MEDIUM) — classify_null_kind reads an empty-but-successful source entry as "source was reached" (families 3+4)

The consolidation removed the drifted duplicate rule (good), but the single

not evidence of contact; treat it like no_route/skipped (retrieval failure)
